# Stop Building SaaS. Build One of These 8 Instead.

**Source:** [Build Great Products - Chris (YouTube)](https://www.youtube.com/watch?v=iJgBQy2k9hk)  
**Date:** October 21, 2026  
**Duration:** 34:58

---

## Executive Summary

**The Thesis:** Generic SaaS is dying. There are 8 specific types of software that will thrive in the AI era.

**Why Traditional SaaS Is Dead:**
1. Building got incredibly cheap (weekend clones)
2. Agents are now equal users alongside humans
3. Pricing moved from features to outcomes

**What Replaces It:** Software built around trust, taste, data, and distribution—not code.

---

## Why Traditional SaaS Is No Longer Viable

### Three Structural Changes

#### 1. **Building Got Incredibly Cheap**

**Reality:** You can build complex software in a weekend with AI.

**Implication:** Generic, poorly-designed products are no longer viable businesses.
- They used to work because building was hard (6-12 months, many developers)
- Now the moat isn't the code, it's everything around the code
- The bar for "good software" just got massively higher

**What this means:** Bad software can no longer compete on being "software." You need taste, expertise, data, or distribution.

---

#### 2. **Agents Became Equal Users of Software**

**Change:** Software now has two types of users:
- **Humans** (clicking UI)
- **Agents** (via APIs, CLIs, MCPs, accessing without UI)

**Implication:** Your software must be both human-friendly AND agent-accessible.

**New options:**
- Human-first UI + agent capabilities
- Agent-only (headless) - no UI needed
- Hybrid approaches

---

#### 3. **Pricing Moved to Outcomes, Not Features**

**Old:** "Pay per login" or "pay per feature"

**New:** "Pay for results"

**Why:** People want problems solved, not tools.

**Example:** Not "pay for accounting software" → "pay for accurate tax return filing"

---

## The New Moats (Replacing Code)

Since code is now commoditized, defensibility comes from:

### **Expertise**
How deeply do you understand your specific niche?

### **Taste**
Quality of experience, brand vision, creative approach, intuitive flows.
- Previously: 6-month redesign cost $100K+
- Now: Test 100 variations in a week with AI
- Taste becomes a defensible moat

### **Data**
Industry-specific data not in AI's training set = moat.
- You have it; competitors don't
- Cross-company patterns visible only to you
- Example: Strava heat maps, Waze traffic, Glassdoor salaries

### **Distribution**
Access to audience, community, customers.
- Building isn't a moat anymore (viral video can give it away overnight)
- Distribution is what gets you the customer shots
- Other 5 moats make it last

## The 8 Types of Software to Build Now

### **#1: Software-Enabled Services** (Full-Stack AI)

**Concept:** You don't sell the software. You sell the outcome.

**Model:**
```
Front: Look like an agency
  - Sell outcomes (invoices processed, leads generated, ads delivered)
  - Charge agency pricing (high)
  - Client pays for results, not tool

Back: Run on your custom AI + software
  - Do work manually at first
  - Systematize with AI
  - Automate bit by bit
  - Eventually: well-oiled machine, mostly automated
```

**Real Examples:**
- Pilot + Crosney (accounting firms powered by AI)
- Legal firms using AI to handle basic work
- Creative agencies (design, copywriting, branding) with AI amplification

**Why it works:**
- Before: 20-person firm needed per client
- Now: 2 people + AI per client
- Same outcome, 10x profitability or same profit at 10x efficiency

**Who should build this:**
- Service business operators with existing expertise
- Agencies/freelancers with proven processes
- Anyone with deep industry experience

**How to start:**
1. Take your proven service process
2. Map it out (where are the manual, repetitive parts?)
3. Layer in AI/automation to handle those parts
4. Sell the same outcome, but faster/cheaper

---

### **#2: Vertical Agent Harness**

**Concept:** A controlled environment for AI agents specialized in one niche.

**Definition:**
A "harness" = everything around the AI model
- Rules
- Tools
- Knowledge (domain-specific)
- Workflows
- Memory
- Context

**Real Examples:**
- Harvey (legal agent harness)
- Abridge (healthcare agent harness)
- Evenup (litigation agent harness)

**Custom Example from Builder:**
- "Lawwell" = Dungeons & Dragons agent harness
  - Custom knowledge about D&D rules
  - Tools for campaign planning
  - Memory of player characters
  - Workflows for session management
  - Helps DMs run campaigns with AI assistance

**Why these work:**
- General models (Claude, GPT) are general-purpose
- The gap = the specialized harness you build
- Gets better as base models improve
- Gets cheaper as model costs drop

**Who should build this:**
- Deep expertise in a specific niche
- Passion for a particular domain
- Understanding of pain points in that niche

**Industries ripe for this:**
- Every single niche (not just accounting/legal)
- Underexplored: creative fields, hobby communities, specialized work

---

### **#3: Headless AI Software**

**Concept:** Software with NO user interface. Purely agent-accessible.

**Access methods:**
- CLI (Command Line Interface)
- API
- MCP (Model Context Protocol)

**Real Examples:**
- **Eyedropper** (CLI tool)
  - Pulls design system from cloud
  - Brings into project
  - Agents use it to maintain design consistency
  - No UI needed

- **Posture** (social media scheduler)
  - Agents schedule posts via CLI/MCP
  - No UI required
  - Or: optional UI for viewing/monitoring

**Why it works:**
- Agents don't need UIs
- Simpler to build (no interface design)
- Cleaner integration into agent workflows
- Usage-based pricing fits naturally

**Who should build this:**
- Builders with specific data sources
- Narrow, hard skills (can't easily be replicated)
- Technical + non-technical founders (AI coding handles complexity)

**Trap to avoid:**
- Models might bundle 3 of these into their own tools next quarter
- Race to build before that happens

---

### **#4: Agent-Native Systems**

**Concept:** Plugin + Visual Dashboard hybrid

**Structure:**
```
Plugin/Skill: Runs inside Claude, ChatGPT, etc.
  - Executes workflows
  - Automates processes
  - Calls external tools

Dashboard: Visual layer
  - Shows progress
  - Displays results
  - Collects data on outcomes
  - Allows visualization of complex flows
```

**Real Example: Product OS**
Builder's own system takes users through:
1. Defining idea
2. Validating it
3. Figuring out product offer
4. Designing
5. Building design system
6. Building product
7. Deploying
8. Getting first customers

Each step is a plugin workflow. Dashboard shows progress through all 8.

**Perfect for:**
- Coaches with repeatable methods
- Consultants with proven processes
- Educators with structured curricula
- Anyone with IP/methodology

**How it works:**
1. User installs plugin in their AI tool (Claude, ChatGPT, etc.)
2. Runs workflow inside that tool
3. Dashboard syncs with results
4. Collects data on student/client progress
5. You monetize via plugin subscription + dashboard

**Why users love this:**
- No new app to download
- Works inside tools they already use
- Familiar interface (ChatGPT, Claude)
- Can use with their preferred AI tool

---

### **#5: Taste-Led Niche Products**

**Concept:** Build for 1,000 true fans, not for mass market.

**Model:**
- Niche community
- Specific audience
- Taste-driven (not conversion-optimized)
- Creative approach
- Not trying for $1M exit—fits into broader business

**Who has advantage:**
- Creators with existing audience
- Anyone with passionate community
- People who care deeply about specific niches

**Real Example from Builder:**
- Roller coaster tracking app
- Came from personal passion for theme parks
- Built for hyper-specific community
- Not trying to compete with mass-market apps
- Would sell to 1,000 people who love roller coasters

**Why it works:**
- Low CAC (existing audience)
- High retention (serving fans, not strangers)
- Premium positioning (serving people who care)
- Defensible moat = caring more than anyone else

**Key insight:**
> "Caring more than anyone else is the scarce thing."

**Who should build:**
- Anyone with audience/community
- Creators in any space
- People with deep passion for specific niche
- Founders who'd rather serve 1K passionately than millions generically

**Trap:** Trying to build for everyone instead of going super-specific.

---

### **#6: Ambient Consumer Agents**

**Concept:** AI agents living in the apps people already use (messaging, chat).

**Real Examples:**
- **Meta AI in WhatsApp**
  - Talk to AI in group chats
  - Schedule things, get info, plan
  - No new app needed

- **Muse, Instinct, ChatGPT in iMessage**
  - Agent in your text messages
  - Seamless integration
  - Not a separate app

- **Grokbot**
  - Consumer agent in popular messaging

**Why it works:**
- No app friction (app download fatigue is real)
- Lives where people already are
- Seamless UX
- Agents can plan, book, remember things

**The challenge:**
- Hyper-competitive space
- Must abstract agent complexity away
- Aunt (non-tech user) must understand value immediately
- Conversation UX must feel natural

**Key insight:**
Most people don't understand agents. Your UX must hide that complexity.

**Who should build:**
- Ambitious founders wanting to "shoot for the moon"
- Consumer product experts
- People who understand families, clubs, teams
- Willing to take big risks

**Trap:** Novelty > utility. Don't build just because agents are cool.

---

### **#7: Proprietary Data Products**

**Concept:** "Anyone can copy your app, but nobody can copy your data."

**Key concept: In-Distribution vs. Out-of-Distribution Data**
- **In-distribution:** Data in AI training sets (public, common)
- **Out-of-distribution:** Unique data NOT in training sets
  - This is rare and valuable
  - AI agents can't access it without your product

**Real Examples:**
- **Strava heat maps** (aggregated running/cycling routes)
- **Waze traffic** (real-time traffic from users)
- **Glassdoor salaries** (crowd-sourced salary data)

**The Model:**
1. You have/collect unique industry data
2. Build product around it
3. Make it agent-native (APIs, so agents query it)
4. Charge access
5. Moat = data nobody else has

**How to find opportunities:**
- What data exists inside specific industries that AI doesn't know?
- What patterns emerge across 10 companies but no single company sees?
- What's in people's heads that could be captured?

**Who should build:**
- Business owners with industry data
- Community managers with aggregate insights
- Anyone with access to out-of-distribution data

**Implementation:**
- Build data collection into your product
- Make it agent-accessible
- Charge for data access
- Moat grows as you collect more data

---

### **#8: Open-Source Core Products**

**Concept:** Free code, paid services around it.

**Model:**
```
Open-source: Free
  - Core functionality is free
  - Code on GitHub
  - Anyone can self-host
  - Works as marketing/distribution

Paid tiers:
  - Cloud hosting (you run it)
  - Premium features (built on data)
  - Support
  - Advanced tools
  - Community/sponsorship
```

**Real Examples:**
- **Superbase** (open-source backend)
  - Code is free
  - Money: cloud hosting, managed service

- **PostHog** (open-source analytics)
  - Core is free/open
  - Money: paid cloud version, data insights

- **Cal.com** (open-source scheduling)
  - Free self-hosted version
  - Money: hosted version, advanced features

- **PostgreSQL** (database, historically)
  - Free code
  - Companies charge for hosting/support

**Why it works:**
- Open-source IS the marketing
- Removes copy concerns (anyone can clone)
  - But they can't replicate your community/hosting/support
- Community becomes competitive advantage
- Network effects around your hosted version

**Who should build:**
- Developers happy working in public
- Builders wanting to grow communities
- People with clear monetization path (hosting, support, data)
- Not trying to hide implementation

**Trap:** Giving away all value. Make sure paid tier is genuinely valuable:
- Managed hosting
- Support
- Premium features (data-driven insights)
- Not just "free code + paid code"

## Quick Decision Framework

**For each opportunity: Who has advantage?**

| Type | Best For | Requirements |
|------|----------|---------------|
| **Software-Enabled Services** | Service business owners | Proven process, existing clients |
| **Vertical Agent Harness** | Deep niche experts | Specific domain knowledge |
| **Headless AI Software** | Data specialists, narrowly-skilled builders | Specific data source or hard skill |
| **Agent-Native Systems** | Coaches, consultants, educators | Repeatable method, proven results |
| **Taste-Led Niche** | Creators, passionate founders | Audience or community |
| **Ambient Consumer Agents** | Ambitious consumer product builders | Willing to take big bet |
| **Proprietary Data** | Industry insiders, data collectors | Access to out-of-distribution data |
| **Open-Source Core** | Public builders, community-focused | Clear monetization path beyond code |

## Key Insights Across All 8

### All Get Better as Models Improve

**Universal truth:** If AI models improve, your product improves.
- Software-enabled services: processes run more efficiently
- Agent harnesses: agents become more capable
- Headless software: agents make better use of tools
- Data products: AI extracts more value from data
- etc.

Contrast: Generic SaaS dashboard
- Better models don't make it better
- Still the same features as 5 years ago
- Vulnerable to being copied

---

### The Real Moat Isn't Code

**Why generic SaaS dies:**
- Code can be copied (and will be)
- Generic features are interchangeable
- No defensibility

**Why these 8 types thrive:**
- Built on expertise (rare)
- Built on taste (personal)
- Built on data (proprietary)
- Built on distribution (takes time)
- Built on community (hard to steal)
- These can't be cloned in a weekend

## The Core Reframe

**Old mentality:** "Build the best generic software and win through features."

**New mentality:** "The AI era rewards specificity, taste, domain expertise, and distribution. Generic software is dead."

**Bottom line:**
> "Software isn't dead. Generic software is dead. There is huge room for great AI-native, agent-native products."

## Connection to Your Thesis: Knowledge → Zero, Trust → 100

**Knowledge → Zero:**
- Generic SaaS (knowledge-based features) commoditizes overnight
- AI can build it in a weekend
- Copying is trivial
- Feature parity = no moat

**Trust → 100:**
- All 8 types require trust:
  - Trust you understand the industry (harness, data, services)
  - Trust your taste (niche products)
  - Trust your community (open-source, consumer agents)
  - Trust your expertise (coaches, consultants)
  - Trust you'll solve their specific outcome (all types)

**The strategic implication:**
Your advantage isn't code, features, or generic knowledge. It's trust: that you understand their specific problem better than anyone and can solve it.
